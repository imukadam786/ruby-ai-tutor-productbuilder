§1 — Architecture

The maths diagnostic is entirely client-side — no API calls are made during question administration or placement computation. A random question bank is loaded once on start; all subsequent logic runs in the browser.

§3 — Gate System

Bank Gate System (A–D, original)

The original gate field in each bank task groups the 18 domains into 4 broad bands aligned with school grade expectations.

Bank GateDomainsCurriculum Stage
AM001 – M006Foundational — counting, addition, subtraction, multiplication
BM007 – M010Intermediate — decomposition, fractions, ratio, integers, BODMAS
CM011 – M014Senior — algebra, linear equations, quadratics, functions
DM015 – M018Advanced — logs, trig, differentiation, multi-step problems

Binary Search Gate System (A–F, new)

The binary search uses a finer 6-gate system for precision placement. Each search gate corresponds to a pair of domains. Note: M015–M018 (Bank Gate D) are not part of the search — they appear only in the confirmation phase.

Phase 1 — Anchor (2Q)

The student's school grade determines which gate is used as the anchor. Two questions are drawn from that gate's two domains.

School GradeAnchor Gate (Index)Domains asked
Grade 1 – 3Gate A (0)M001, M004
Grade 4 – 6Gate B (1)M005, M006
Grade 7 – 9Gate C (2)M007, M008
Grade 10+Gate D (3)M009, M010

Pass rule: 2 of 2 correct → search upward. 0 or 1 correct → search downward (Option B).

Phase 2 — Binary Search Step 1 (2Q)

Search window is grade-banded. The midpoint gate of the current window is tested.

Grade BandSearch WindowPass → new windowFail → new window
Grade 1 – 3A – B [0,1]Anchor+1 → B [1,1]A-1 → empty
Grade 4 – 6A – C [0,2]Anchor+1 → C [2,2]Anchor-1 → A [0,0]
Grade 7 – 9B – D [1,3]Anchor+1 → D [3,3]Anchor-1 → B [1,1]
Grade 10+C – F [2,5]Anchor+1 → F [4,5]Anchor-1 → C [2,3]

Phase 3 — Binary Search Step 2 (2Q)

The updated window from Phase 2 drives a second midpoint. If the window is empty (search converged), a gate adjacent to lastPassedGateIdx is selected as the redundant step to maintain the 9-question total.

After Phase 3, lastPassedGateIdx holds the highest gate index where the student passed 2/2.

Phase 4 — Confirmation (3Q)

Three single-domain questions are selected from three consecutive gates centred on lastPassedGateIdx, clamped to valid indices [0–3] so all three exist:

confirmGate = clamp(lastPassedGateIdx, 0, numGates − 3) Gates tested: [confirmGate, confirmGate+1, confirmGate+2] One question per gate (first domain of that gate only)

These tasks are assigned block = 3 for placement block computation.

Probe Tasks
Up to 2 probes per phase may be triggered by specific error signals. Probes are choice-based and do not count toward the 9-question total. They drain before the next primary task advances.

§5 — Placement Computation

After all 9 questions, computePlacement(results, grade) runs in the browser. It uses the domain results gathered across all 4 phases, filling gaps with grade-based assumptions.

Gate Pass Definitions

hardGatePassed = passed("M006", "A") // Multiplication is the hard gate gateA = passed("M001", "A") && passed("M004", "A") gateB = passed("M005", "A") && hardGatePassed gateC = passed("M007", "B") && passed("M008", "B") gateD = passed("M009", "B") && passed("M010", "B") gateE = passed("M011", "C") && passed("M012", "C") gateF = passed("M013", "C") && passed("M014", "C")

The passed(domain, gate) function returns scoreMap[domain] if the domain was tested, or falls back to grade >= GATE_GRADE_THRESHOLD[gate] for untested domains.

§6 — Probe Tasks

Three hardcoded probes exist. They are triggered when a primary task is answered incorrectly with a matching error signal. Probes use multiple-choice format and resolve before the next primary task.

Probe IDTrigger ErrorTrigger ConditionQuestionTests
PROBE_PV1 ERR_DIGIT_SWAP Block 1 only "What is the tens digit in 473?" Place value — digit position
PROBE_CS1 ERR_COUNT_SKIP Block 1 only "Count on from 13. What is the next number?" Counting sequence continuity
PROBE_FF1 ERR_INVERT or ERR_PART_WHOLE Block 1 or 2 "Which of these shows one half?" Fraction representation (1/2 vs 2/1)
Gap
Only 3 probes cover only 3 error types out of 41 defined error signal codes. The vast majority of detected errors do not trigger any follow-up probe question.

§12 — Reading Diagnostic Flow

Unlike maths, the reading diagnostic is fully linear — all 16 tasks are administered in a fixed order with no early exit, binary search, or phase adaptation.

Welcome
Intro Screen
0 questions
Tasks D01 → D18
All 16 Tasks (Fixed Order)
16 tasks — always completed in full
Result
Placement + Skill Map
API call → entry skill

Per-Task Flow

  1. Task card displayed with prompt and stimulus (if any)
  2. Student responds via the task's answer mode (voice, tap, flash)
  3. Response POSTed to /api/reading/diagnostic/evaluate
  4. OpenAI evaluates response → returns { correct, score, errorType }
  5. Result stored; next task displayed
  6. After D18: all results POSTed to /api/reading/diagnostic/placement
  7. Placement calculator returns entrySkillId + autoCompletedSkillIds
AI Dependency
All voice-mode tasks (D01, D02, D09, D10, D12, D13, D14, D16) require an OpenAI API call to evaluate. Audio-tap tasks (D03–D06) are evaluated client-side. If the OpenAI call fails, the system falls back to: length > 2 chars → pass (score 0.75); else → fail (score 0.3, ERR_SOUND_RECALL).

§14 — Placement Decision Engine

After all 16 tasks complete, reading-placement-calculator.ts applies three rules in order.

Rule 1 — Foundation Failure

If D01 (Phonological Awareness) OR D02 (Phoneme Isolation) fail → place at R1.T1.A1 (the very start of the tree). No skills auto-completed.

Rule 2 — First-Failure Scan

Scan diagnostic tasks in sequence: D01 → D02 → D03 → D04 → D09 → D10 → D11 → D12 → D13 → D14 → D15 → D16 → D17 → D18. Stop at the first task where score < passThreshold. Entry skill = that task's mapsToSkill. All skills mapped to tasks before the failing task in the sequence are auto-completed.

Skill Sequence (Auto-Completion Order)
36 skills total across 5 levels. Auto-completion marks all skills preceding the entry skill as mastered. The skill sequence used is: R1.T1.A1 → … → R1.T3.A3 → R2.T1.A1 → … → R2.T3.A3 → R3.T1.A1 → … → R3.T2.A2 → R4.T1.A1 → … → R4.T3.A2 → R5.T1.A1 → … → R5.T3.A1

Rule 3 — All Pass

If all 16 tasks pass → entry at R5.T1.A1 (advanced comprehension). All 33 preceding skills are auto-completed. hardGatePassed = true.

Hard Gate Definition Issue
hardGatePassed is always set to true in the reading diagnostic regardless of performance. There is no equivalent to the maths multiplication hard gate — no single skill blocks progress to advanced content.

§18 — Coverage Gaps

Maths Coverage Gaps

GapDetailImpact
M002 & M003 never tested Counting Sequence and Place Value are in Bank Gate A but have no corresponding Binary Search Gate. They only surface via probe tasks (conditional). A student with a counting or place value deficit may be placed too high because these domains are never directly administered.
M015–M018 only in confirm phase Advanced domains (logs, trig, differentiation, multi-step) appear in the confirmation phase as single questions only — never in anchor or binary search. Placement at Levels 15–17 relies on only 1 question each from M015–M017. Confirmation is sparse for advanced students.
3 probes for 41 error codes Only 3 error types (ERR_DIGIT_SWAP, ERR_COUNT_SKIP, ERR_INVERT/ERR_PART_WHOLE) trigger follow-up probes. 38 error codes are detected but never investigated further.
Early exit defined but not called evaluateEarlyExit() exists in diagnostic-engine.ts with 3 conditions but is not imported or called in MathsDiagnosticPlacement.tsx. Frustrated or overwhelmed students always complete all 9 questions.
Maths diagnostic never asks M002/M003 directly Binary search gates A–F skip M002 and M003 entirely. The probe tasks for these domains only fire if a related error is detected on M001 or M004. Counting sequence and place value gaps may be missed for students who answer M001/M004 correctly but for the wrong reasons.

Reading Coverage Gaps

GapDetailImpact
D07 and D08 missing Two diagnostic tasks are absent from the sequence with no replacement. The gap falls between consonant blends (D06) and long vowels (D09). Unknown skill coverage lost. The skill tree may have atomic skills that are completely undiagnosed.
19 of 36 skills have no diagnostic task Only 17 skills have a direct mapsToSkill mapping. Skills in R1.T1, R1.T2.A2, R1.T3.A2–A3, R2.T1.A2–A3, R2.T2.A2, R2.T3.A2–A3, R3.T1.A2–A4, R3.T2.A2, R4.T1.A2, R4.T2.A2, R4.T3.A1–A2, R5.T1.A2, R5.T2.A1–A2, R5.T3.A1 are never tested. Students placed into untested skills begin with no prior diagnostic evidence for that skill. First-session questions substitute for missing diagnostic coverage.
R2.T3.A1 tested by 3 separate tasks D09 (CVCe), D10 (vowel teams), and D12 (r-controlled) all map to R2.T3.A1. First-failure scan stops at whichever comes first. A student failing D09 is placed at R2.T3.A1 and the D10/D12 data is not used to distinguish which vowel pattern is the problem.
hardGatePassed always true The reading placement always returns hardGatePassed = true. There is no equivalent to the maths multiplication gate. No mechanism to flag a student who has a foundational gap serious enough to block further skill tree access.
Linear flow — no adaptive routing Every student answers all 16 tasks in the same order regardless of performance. No branching or early routing based on early failures. A Grade R student who fails D01 still answers D14 (multisyllabic decoding). A Grade 5 student who passes D06 still spends time on D03/D04.
AI evaluation dependency 8 of 16 tasks rely on OpenAI for scoring. Failure or latency degrades student experience and accuracy. Fallback logic (length > 2 → pass) is inaccurate and can produce false positives.
D11 passage mismatch with D17/D18 D16 uses a specific fluency passage; D17/D18 comprehension questions reference "Maya" — a different character not in the D16 passage. The comprehension questions appear to reference a different unpublished passage. D17 and D18 may be testing comprehension of a passage the student never read, invalidating results.
50 reading question banks unused The randomised bank infrastructure exists and the component loads a bank, but the hardcoded DIAGNOSTIC_TASKS array is used instead. No question variation across sessions. Repeat diagnostic completions use identical items.
