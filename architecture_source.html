Missing Blocks — Planned Architecture
Ruby AI Tutor
Page 6 of 7
The blocks below are designed in the UI (settings billing page, video placeholder, download report button) but have no backend implementation yet. All grey dashed = not built.
🔐 Authentication System

No login, no user accounts. Students identified only by localStorage. Loses progress on device switch. Recommended: Supabase Auth or Clerk for email + Google OAuth.

🗄️ Backend Database

All profile, mastery, and session data stored in browser localStorage. Resets on clear. Target: Supabase PostgreSQL with tables for users, skill_mastery, sessions, error_history.

💳 Payment Gateway

Billing UI exists in Settings but no integration. No subscription plans enforced. Target: Stripe Checkout + Customer Portal + webhook handlers for plan gating.

📹 Video Learning

"Watch" mode in sidebar shows "Coming soon" placeholder. Target: Mux or Cloudflare Stream for low-latency adaptive video. Curriculum-aligned videos per skill tier.

📊 Analytics Platform

No behavioural tracking beyond local streak data. No funnel analysis, no drop-off detection. Target: Posthog (open-source) for user behaviour + learning analytics dashboard.

🚨 Error Monitoring

No production crash reporting. API errors silently swallowed. Target: Sentry for real-time error tracking, performance monitoring, and API failure alerts.

📧 Email Service

No transactional email. No welcome email, weekly progress summary, or subscription receipts. Target: Resend (modern API) for automated parent/student emails.

📄 PDF Progress Reports

Download button in Settings does nothing. Target: React PDF or Puppeteer-based report generation covering skill mastery, error patterns, and weekly progress.

👩‍🏫 Teacher Dashboard

Single-student app only. No class management, no multi-student view, no teacher login. Required for school licensing. Target: separate teacher role + class overview UI.
